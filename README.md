# Download Speed CLI

Консольный скрипт на Node.js для замера скорости скачивания с заданного HTTP(S)-адреса.
Выполняет **10 последовательных загрузок**, каждый раз дожидаясь полного тела ответа.
Внешние зависимости для запуска не нужны.

## Требования

- Node.js **22.13 или новее**.
- Доступ к выбранному HTTP(S)-ресурсу.

## Запуск

```sh
git clone https://github.com/aggravatingbu/download-speed-cli.git
cd download-speed-cli
node download-speed.js "https://example.com/large-image.jpg"
```

Замените адрес на прямую ссылку на достаточно большой файл, например изображение.
URL с параметрами заключайте в кавычки. Скрипт скачает файл **10 раз**:
для файла размером 20 MiB это около 200 MiB полезных данных.

Тайм-аут одной полной загрузки по умолчанию — 30 секунд. Его можно изменить:

```sh
node download-speed.js "https://example.com/large-image.jpg" --timeout 60
node download-speed.js --help
```

Также работает `npm start -- "<URL>" --timeout 60`.

## Результат и единицы

Пример вывода (значения приведены для иллюстрации):

```text
Завершено запросов: 10
Среднее время запроса: 1000.00 мс
Общий объём: 104857600 байт (100.000 MiB)
Суммарное время загрузок: 10.000 с
Скорость скачивания: 10.000 MiB/s (83.886 Mbit/s)
```

- **MiB/s** — мебибайты в секунду; 1 MiB = 1 048 576 байт.
- **Mbit/s** — мегабиты в секунду; 1 Mbit = 1 000 000 бит, 1 байт = 8 бит.
- Время запроса выводится в миллисекундах, суммарное время — в секундах.
- Объём считается по реально прочитанным байтам тела, а не по `Content-Length`.

Расчёт:

```text
среднее время = сумма времени 10 загрузок / 10
скорость MiB/s = суммарные байты / суммарные секунды / 1 048 576
скорость Mbit/s = суммарные байты × 8 / суммарные секунды / 1 000 000
```

Используется монотонный таймер `performance.now()`. Для каждой загрузки
время отсчитывается от начала запроса до последнего байта ответа; оно включает
установку соединения, если она нужна, ожидание сервера и перенаправления.
Скорость — отношение общего объёма к общему времени, **не среднее отдельных скоростей**.

## Поведение и ограничения

- Только HTTP и HTTPS; системная проверка TLS-сертификатов не отключается.
- До 5 перенаправлений на одну загрузку, включая относительные ссылки.
  Считается объём конечного успешного ответа; промежуточные тела прочитываются,
  их время входит в замер, но их байты не входят в объём ресурса.
  Поэтому при перенаправлениях сетевых HTTP-запросов будет больше 10.
- Любой ответ 2xx считается успешным, включая пустой 204.
- Файл читается потоком и не сохраняется на диск или целиком в памяти.
- Заголовок `Accept-Encoding: identity` запрашивает несжатый ответ.
  Если сервер всё же присылает сжатое тело, считается его сжатый размер:
  скрипт не выполняет автоматическую распаковку.
- `Cache-Control: no-cache` просит перепроверить ресурс, но не гарантирует
  обход кешей сервера или CDN; случайные параметры к URL не добавляются.
- HTTP-заголовки, служебные данные HTTP/TLS/TCP и повторно переданные пакеты
  не входят в подсчитанный объём.
- Тайм-аут охватывает **всю загрузку**, а не только простой сокета,
  и не сбрасывается при перенаправлениях.
  Допустимы значения от 0.001 до 2147483.647 секунды с точностью до 1 мс.
- При HTTP-ошибке, сетевой ошибке, обрыве тела или тайм-ауте замер прекращается.
  Повторов нет, частичная статистика не выдаётся, сообщение идёт в `stderr`,
  код завершения — **1**. При успехе и для `--help` код — **0**.

Это скорость получения данных **с выбранного сервера**, а не гарантированная
пропускная способность интернет-тарифа. На неё влияют размер файла, задержка,
нагрузка сервера, кеши и повторное использование соединений. Небольшой файл
в основном измерит задержку, поэтому для оценки пропускной способности лучше
взять крупный ресурс без перенаправлений.

## Проверки и тесты

Зависимости разработки нужны только для статического анализа:

```sh
npm ci --ignore-scripts
npm run check
```

`npm run check` последовательно запускает:

1. `node --check` — синтаксические проверки.
2. ESLint — статические правила для JavaScript, без допуска предупреждений.
3. TypeScript — строгую проверку типов JavaScript через JSDoc, без генерации файлов.
4. `node --test --experimental-test-coverage` — тесты и отчёт о покрытии.

Отдельные команды: `npm run lint`, `npm run check:types`, `npm test`.
Только тесты можно запустить без установки зависимостей: `node --test`.

Тесты не обращаются в интернет: они запускают локальный HTTP-сервер на случайном
порту. Проверяются формулы, ровно 10 последовательных загрузок, чтение полного
тела и подсчёт байтов, пустые и сжатые ответы, перенаправления, тайм-ауты,
обрывы соединений, ошибки HTTP и консольный интерфейс. Для воспроизводимости
версии анализаторов зафиксированы в `package-lock.json`.

GitHub Actions запускает те же проверки на Windows и Linux с Node.js 22 и 24.
